Project

旅の最中は、楽しむことに集中する。
気づきは、帰ってから生まれる。

旅行中、人は記録のために頭を使いたくない。でも帰った後、写真だけでは旅は思い出されない。Arcoは、スマホがすでに集めているデータと、仲間が残した断片を、旅が終わった後に統合する。旅の最中には気づかなかった発見が、自動で生まれる。

Category

Target
友達と旅行する大学生
Tools
Figma ／ Claude ／ ユーザーリサーチ
Period
2026年（数週間）
Problem

写真はある。でも、旅として繋がらない。

旅の記録は、いつも個人の断片で終わる。3つのペインが、旅の記憶を取りこぼしていた。

01

空気感が、残らない

写真だけでは、会話・感情・匂いまでは戻ってこない。

02

記録が、分断されている

友達がそれぞれ撮った写真は、後から共有されない。

03

写真が、埋もれる

枚数だけが増えて、整理されないまま記憶から消える。

「写真だけだと、その時の気持ちとか匂い、会話までは思い出せない。」

— 女子大学生（感性派・エモさ重視）
Research → Findings

属性を意図的に散らした5名に、構造化アンケート＋自由記述を実施。数で傾向を掴み、自由記述で本人の言葉を拾った。

Concept

誰もが持っているスマホの機能だけで、
今までにない旅の体験を作る。

集めるのは、スマホがすでに持っているデータ。「儀式」が、それを“旅”に変える。追加で何も買わない・入れない。

集まっているもの

追加で何も買わない・入れない
  • 📍GPS（Google Mapsタイムライン）
  • 🖼️写真（カメラロール）
  • 👟身体データ（ヘルス・歩数）
  • 👥仲間の記録（共有された写真・メモ）

Experience Flow

旅前 ／ 旅中 ／ 旅後で、役割を分ける。

「ユーザーがすること」と「アプリがすること」を、フェーズごとに切り替える。

PHASE 01
旅前 — セットアップ
User旅の名前を決め、招待リンクをLINEで送る。
App参加者のアバターを並べ、全員揃うと開始ボタンを灰色からコーラルへ。
PHASE 02
旅中 — ミニマル
User楽しむことに集中する。気が向いた時だけ写真やメモを足す。
App表示は「旅行中」のみ。GPS・写真・歩数・仲間の断片を裏で集め続ける。
PHASE 03
旅後 — 自動生成
User帰宅したら旅を「終了」。リールを観て、発見タブで気づきを読む。
App収集データを統合・解析し、ハイライトリール（8枚）とインサイトカードを自動生成。

Highlight Reel

旅後の感動を運ぶ、8枚のフルスクリーンカード。

Spotify Wrapped式。旅の数字と発見を、1枚ずつ送り出す。「データを見せる」のではなく「ドラマとして送り出す」。

01 / 旅の総時間 — 数字で旅を立ち上げる
02 / 総移動距離 — 数字が立つカード
03 / 一番歩いた人 — 人の物語が立つカード
07 / 全員が重なった瞬間 — 集団のドラマ
08 / 締め — 感情を閉じるカード

全8枚は「定量データ × 集団のドラマ」を交互に配置している。数字が立つカード、人の物語が立つカード、そして感情を閉じるカード。1枚ずつ全画面で送り出すことで、データを“ドラマ”に変える。

Main View

リールの余韻のあと、4つのタブでじっくり読み解く。

旅後のメインビュー。「発見」で驚き、「タイムライン」で辿り、「マップ」で俯瞰し、「みんな」で視点の違いを知る。すべて、集めたデータからの自動生成。

Key Insight

感覚的な違和感（「なんか嫌」）をコンセプトとの矛盾として翻訳できると、ローカルな修正ではなく、構造的な設計判断に変わる。

Iteration 02

割り勘機能を、意図して入れなかった。

「割り勘機能があったらいいね」は自然な要望。普通なら入れる。でも3つの理由で、採用しなかった。

①

コアと別軸の機能

Arcoのコアは「旅の記憶の再構築」。割り勘は「費用管理」という別領域。入れると“何のアプリか”が曖昧になる。

②

専門アプリが既にある

ワリカン・Splitwiseが解決済み。後発で同じ機能を作っても差別化できない。唯一解ける課題に集中すべき。

③

「入れない」を語れる強さ

何でも入れる設計者より、何をあえて入れなかったかを語れる設計者の方が、UX思考の深さが伝わる。

やらない判断もまた、デザインである。

コアバリューを守るための「却下」は、プロダクトの輪郭を保つ、もうひとつの設計行為だった。

Reflection

このプロジェクトから、持ち帰ったこと。

01 — コンセプト

リソースの再構成

スマホ・GPS・写真・ヘルス・友達の記録。前から在ったものに「儀式」のフレームをかぶせるだけで、旅の体験になった。新しい体験に、新しいハードは要らない。

02 — リサーチ

感覚を、構造へ翻訳する

「グラフがなんか嫌」を、アレルギーで処理しない。「情報の終着点になっていた」というコンセプトとの矛盾まで掘って、初めて構造的な転換ができる。

03 — 判断

やらない判断もデザイン

要望を聞くことと、実装することは違う。スコープを絞る判断は、コアバリューを守るための設計行為。輪郭は「何を入れなかったか」で決まる。

Why self-made

ポートフォリオは、既製のサービスに合わせて作るもの——という前提を、まず疑った。

採用の場で見られているのは、並べた作品だけじゃない。「どう作る人か」も含めて自分だと思う。だから中身に器を合わせるより、伝えたい順序のために器ごと設計した。テンプレートに自分を削って収めるのとは、逆の選び方をしている。

Decisions — 制約を、選んだ
00

ライブラリ 0

アニメーションも画面遷移も、フレームワークに頼らず手書き（WAAPI・CSS）。全部を理解した状態で持っておきたかった。

01

1ファイル構成

HTML・CSS・JS を1枚に収めた。分割しないことで、全体を頭に乗せたまま速く直せる。

02

ビルドなし

保存して push すれば、1〜2分で公開。手と公開のあいだに、工程を挟まない。

03

検証を自動化

ヘッドレスChromeで各画面をスクショし、レイアウト崩れやエラーを機械的に検出。「最後まで」を、根性ではなく仕組みで支える。

With AI

手が速くなったぶん、判断に時間を使う。

実装の多くは AI（Claude Code）と一緒に書いた。コードを速く出せるようになったぶん、自分の時間は「何を作るか・どんな順で見せるか・どこを引くか」という判断に寄せている。これは卒業研究のテーマ——AI時代にデザイナーは何に時間とエネルギーを使うべきか——への、いまの自分なりの答えでもある。

本当に足りないのは“相談する前”の支援だと気づいた。

教室に居づらい。保健室に行くほどではない。でも、誰かに話したい——。そんな小学生（低〜中学年）の「教室と保健室のあいだ」を支えるために、毎日学校で会えるAIキャラクター「バーチャルン」を提案し、動くプロトタイプまで作った。

01 — 問題発見

保健室は、心と体のセーフスペースになっていた。

保健室側

  • 相談内容が複雑化（心のケアまで広がる）
  • 利用者の増加・保健室登校の長期化
  • 養護教諭は一人職で多忙・孤立しやすい

生徒側

  • 保健室へ行くべきか判断できない
  • 先生に直接話すことへの抵抗感
  • 不調を言葉にできず、我慢してしまう
「どこが痛いか言えない子が多い。大事にしているのは、威圧しない・最後まで聞く・決めつけないこと」— 保健室の先生インタビューより
30–50 人/日
多い日は1日にこれだけの生徒が来室する。現場は、すでに手いっぱいだった。

長谷川 岳
小学3年・8歳・一人っ子
  • 進級のクラス替えで仲の良い友達と離れ、新しいクラスで「友達の作り方」がわからなくなった

  • 10分休憩で会話に入れず、なんとなく保健室へ

岳は、居場所を探して保健室に通うようになった。でも——

保健室に通うことで、逆に孤独感が増していった。

「友達が欲しい」この子に、保健室登校を促すのはミスマッチだった。必要なのは“特別な場所”ではなく、日常の中でゆるくつながり直せる接点だ——という確信が、ここで生まれた。

04 — コンセプトの探索

必要なのは「診断」ではなく、「居られること」だった。

頭痛・腹痛を入力→「保健室へ/様子見」を提案。機械的・医療的で、感情を扱えず却下。

気づき

第三の居場所

教室でも保健室でもない場所。“来る理由”を音楽や交換ノートで作り、趣味でゆるくつながる。

AIキャラに翻訳

「居場所・来る理由・つながり」の核を、毎日学校で会えるAIキャラ＝バーチャルンに昇華した。

05 — プロダクト

話を聞くだけじゃない。次の一歩まで、一緒に。

🧩

整理する

気持ち・体調・状況を分解し、言葉にする。

🧭

判断を助ける

正解を押し付けず「戻る/休む/保健室へ」の選択肢を出す。

🪜

行動を設計する

大きな行動を「席に戻る/深呼吸」など小さく分解。

🤝

人につなぐ

必要なときは保健室・先生へ橋渡しする。

実際のチャットでは、まず共感したうえで「友達と話したい／先生に相談したい／少し休みたい」と選択肢を示し、最後に「まとめる／保健室に行く」で行動と橋渡しに着地する。画面の冒頭には必ず「病気かどうかは分からない、困ったら保健室へ」と、できないことを明示している。

06 — 「毎日会う」ための設計

「困った時だけ」に、しない。

朝の健康観察、今日のひとこと、「◯日れんぞく」の継続要素。必要な時だけ会う関係では、いざという時に頼れない。だから“毎日ゆるく会う友だち”として設計した。学校Wi-Fiでしか使えない仕様が、そのまま「学校に来る理由」にもなる。

「安心して話せる」を、先に約束する。

話した中身は残さない。残すのは「元気／ちょっと／かなり」だけ。いつでもやめられる。すごく困った時は保健室の先生につなぐ——。AIに「やらないこと（診断・命令・評価・個人情報の取得）」を明確に持たせ、それを最初に約束として見せている。

07 — 状態を「整理」する4ステップ

言葉にしづらい不調を、選ぶだけで整理できるように。気分 → 体 → 気持ち → 強さ の順で、毎朝かんたんに。

08 — 保健室側：通知ダッシュボード

先生には、通知・状況把握・傾向を。負担を増やさず、必要な生徒に気づけるように。

保健室ダッシュボード — バーチャルン 通知管理
🔒

会話の中身は、先生にも渡さない。ダッシュボードに出るのは傾向データ（カテゴリ・強さ）と、生徒が任意で書いたコメントだけ。「継続不調」は自動でフラグが立ち、見落としを防ぐ。生徒への約束（残さない）と、先生の“気づける”を両立させた。

Final concept

教室と保健室のあいだに、
生徒一人ひとりの、小さな味方を。

気持ちを整理し／自分で選び／一歩踏み出し／人とつながる。バーチャルンは会話アプリではなく、生徒の自己決定を支える“新しい学校のインフラ”として提案した。
